# Parallel Attestra deployments
Approved in conversation: one Go deployment wizard with bat/sh launchers; initial prefix next; saved choices; explicit empty prefix selects a separate final deployment, never renames test resources. Scopes shared (admin/index), backend (selected environment), both (shared first). Operations preview, deploy, status/health. No cloud execution in implementation.

Library supplies reusable infrastructure and wizard engine; consumer supplies tiny entrypoints, build targets, domains/defaults. Preserve original functional backend/index/admin behavior using extracted compatibility packages, including optional capture, runtime configuration, index publication, Android export. Shared email is externally owned: new stacks reference verified SES identity and must not manage/delete identity or DKIM. Names/state/locks/resources isolate prefix and environment; preserve original email sender domain, prefix confirmation-link origins. Explicitly reject legacy state adoption. Both clears no legacy resources. Final deployment remains separate and test users are disposable.

Retain provider account/region pinning, private local config, secret input redaction, authenticated registry writes, admin MFA and explicit grants. First deployment must initialize appropriate stacks and handle certificate/DNS readiness; no silently skipped dependencies. Cloudflare and Route53 choices need documented supported behavior. Preview cannot implicitly apply infrastructure or DNS. Existing state buckets may be selected and verified; automatic bucket creation is not required.
